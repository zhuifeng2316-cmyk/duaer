# Feature Specification: 自建组件库进向量，分镜墙能用

**Feature Branch**: `feature/019-registry-compose`

**Created**: 2026-09-10

**Status**: Active

**Input**: 口播用自己的组件库，不靠作者背英文名。写分镜墙之前按文案备好组件用图，分镜只选中文动作。

## User Scenarios & Testing

### User Story 1 - 分镜墙用自建库 (P1)

确认文案后系统按口播推断画面动作，从自建组件库检索（向量 + 词表），对上再回落官方目录。分镜墙只见中文动作。

**Independent Test**: 产品口播「列表往下拉就能刷新」对上自建下拉刷新；故事口播不对上产品手势。

### User Story 2 - 组件用图先出再写分镜 (P1)

轮播/界面类组件需要的图在写分镜墙之前生成，写入该镜资源。人物静帧仍在确认分镜之后。C 端不写厂商名。

**Independent Test**: mock 下产品轮播镜在分镜稿里带上 `graphics/…` 路径；失败不挡写分镜。

## Requirements

- **FR-001**: MUST 维护自建组件库（中文标签、题材、别名、可选图片槽）；检索时自建优先
- **FR-002**: 写分镜墙之前 MUST 按已定文案推断动作并生成所需组件用图；缺图跳过槽位仍写分镜
- **FR-003**: 选中后 MUST 把组件用图填进 `graphicVars`；合成稿能读到这些相对路径
- **FR-004**: 人物静帧仍在确认分镜之后；组件用图不是图库静帧，画面里默认不要人脸
- **FR-005**: C 端只显示中文动作

## Success Criteria

- **SC-001**: 单测锁定自建库优先、组件用图路径、故事口播不误配
- **SC-002**: 写分镜接口仍先出分镜墙；浏览器分镜墙无英文 id
