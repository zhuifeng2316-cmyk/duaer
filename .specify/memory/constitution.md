# Duaer Constitution

## Core Principles

### 0. 产品核心：人不出镜的 AI 口播（强制心智）
本产品专门做口播短视频。创作者本人不出镜。成片里的画面、口播、文案、配乐都来自 AI。

主路径：

**上传人物照片 + 选用克隆音色 → 确定文案 → 确定图片分镜 → 生成口播 → 生成配乐 → 合成视频。**

- 成片形态是 **画外音口播 + 克隆静图运动**，不是对嘴型数字人，不是真人出镜拍摄
- 图克隆 = 用人物参考照生成各场景静图，锁同一张脸；支持从一张照片抠出所有头像并勾选、起名，可高清；单人可拆八个朝向，多人可在分镜里同框；**人物形象可复用**：起名后把头像、高清、八个方位收在该人物下，可单张重做；出片点选，不必每次重抠。八个方位是形象包，不是成片图片分镜
- 声克隆 = **可复用的克隆音色**：说话录音保存成音色，出片时点选，不必每次重传；通道若暂无克隆能力，仍须生成口播，C 端不写厂商名
- 出片顺序强制为：**先确定文案内容，再确定图片分镜（含按镜出图），然后生成口播音频，再生成配乐，再由大模型写 HTML 合成稿，最后按合成稿 ffmpeg 合成视频**
- 运动来自合成（推、拉、移、砸切），**禁止把视频模型出片当主路径**
- 文案是成片骨架：每镜有画面、屏幕字、口播、时长、运动
- 语音与配乐都必须尝试生成并混入；失败可无该轨导出，但必须明确告知
- 工作语言一律简体中文。C 端文案禁止出现模型/通道厂商名

### I. Spec-Driven Development（强制）
功能开发必须遵循 Spec Kit：`specify` → `plan` → `tasks` → `implement`。
没有对应 feature 的 `spec.md` / `plan.md` / `tasks.md`，不得大规模写业务代码。

### II. Git 分支模型（强制）
- `main` 生产；`develop` 集成
- 功能在 `feature/<number>-<slug>`；热修 `hotfix/<number>-<slug>`
- 禁止在 `main`/`develop` 上直接堆功能。合并上线后删除短期分支

### III. Mobbin（UI 强制）
凡页面/交互/视觉，实现前对照真实产品屏幕。未装 Mobbin 时，plan 里写明对照产品与缺口。禁止无参考凭空画整页。

### IV. 三层测试（完成前全部必过）
1. 单元测试
2. 接口测试
3. Cursor 内置浏览器：有前端改动不可跳过

### V. 实现纪律
- 先验收再优化；改动贴合 tasks
- 密钥只放 `.env.local`，禁止入库；禁止在日志/UI 打印 `FLOW_API_KEY` / `ARK_API_KEY`
- 可复用人物形象与克隆音色的元数据落本机 SQLite（默认 `storage/duaer.sqlite`）；头像/录音文件仍落盘。C 端不写「数据库」

### VI. 模型网关
文案 / 分镜 / 合成稿 / 配乐 / 口播走点物 Flow（`FLOW_API_KEY`，`FLOW_API_BASE` 默认 `https://flow.dianwu.ai`）。克隆静帧走火山方舟图片生成（`ARK_API_KEY`，`ARK_API_BASE` 默认 `https://ark.cn-beijing.volces.com`）。C 端禁止出现通道或厂商名。
- 文案、图片分镜、HTML 合成稿：`SCRIPT_MODEL`（默认 `gpt-6-astra`）
- 出图：`ARK_IMAGE_MODEL`（默认 `doubao-seedream-4-5-251128`），必须吃人物参考图（抠出的头像或原照）；成片静图强制电影大片光影；头像高清只修原图像素，禁止出图模型重绘脸，界面对照原图
- 口播：`SPEECH_MODEL`；出片选用已保存的克隆音色
- 配乐：`MUSIC_MODEL`（默认 `suno-v5-5`），instrumental
- 合成：大模型先写 HTML 合成稿（时间轴、静帧、字幕、口播/配乐轨），再按稿对静图做运动并混音。禁止视频模型出片。合成稿写坏则用内置电影模版，不得因此失败

### VII. 站点
线上域名 `https://www.duaer.com`（`SITE_URL`）。裸域 `duaer.com` 301 到 www。
